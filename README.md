# Primitive DB

Учебная консольная база данных на Python: создание таблиц, типизированные
CRUD-операции, хранение схем и записей в JSON, подтверждение удаления и кэш
повторных выборок. Приложение и тесты написаны с помощью функций, без классов.

## Установка и запуск

Требуются Python 3.12+, uv и make. Команды выполняются из корня репозитория:

```bash
git clone https://github.com/davidzakharyan0-design/project2.git
cd project2
make install
make run
```

Эквивалент без make:

```bash
uv sync --locked --dev
uv run database
```

Проект использует uv, выбранный на этапе инициализации. Поэтому зависимости
описаны в поле `dependencies` секции `[project]`, а Ruff — в группе
`dev` секции `[dependency-groups]`.
Poetry для установки и проверки не требуется. `uv.lock` фиксирует версии.
Вместо команды `database` можно использовать алиас `project` или запуск
`uv run python -m primitive_db.main`.

## Команды

| Команда | Назначение |
| --- | --- |
| `create_table users name:str age:int is_active:bool` | Создать таблицу |
| `list_tables` | Показать список таблиц |
| `insert into users values ("Sergei", 28, true)` | Добавить запись |
| `select from users` | Вывести все записи |
| `select from users where age = 28` | Выбрать записи по условию |
| `update users set age = 29 where name = "Sergei"` | Изменить записи |
| `delete from users where ID = 1` | Удалить записи с подтверждением |
| `info users` | Показать схему и число записей |
| `drop_table users` | Удалить таблицу и данные с подтверждением |
| `help` / `exit` | Справка / выход |

Типы: `int`, `str`, `bool`. Все поля обязательны, при вставке значения идут
в порядке столбцов без ID. `ID:int` добавляется автоматически, новый ID —
максимальный среди текущих записей плюс один, для пустой таблицы — 1.
После удаления максимального ID он может использоваться повторно.
Изменять ID нельзя. Имена таблиц и столбцов — идентификаторы Python;
регистр имеет значение, повторяющиеся столбцы запрещены.

Строки вводятся в одинарных или двойных кавычках; пробелы и запятые внутри
кавычек сохраняются. Поддерживаются экранированные кавычки, обратная косая черта
и последовательности `\n`, `\r`, `\t`. Целые числа и `true`/`false` вводятся
без кавычек. Типы проверяются строго: `true` не считается целым числом.

`where` поддерживает одно равенство. `update` может менять несколько полей:
`update users set age=30, is_active=false where ID=1`.
`update` и `delete` требуют условие и обрабатывают все совпавшие записи.

## Хранение и архитектура

```text
src/primitive_db/
├── __init__.py
├── constants.py   # Пути, типы, ограничения и маркеры результатов
├── core.py        # Таблицы, CRUD и проверка данных
├── decorators.py  # Обработка ошибок, подтверждение, время и кэш
├── engine.py      # Консольный цикл и сохранение результатов
├── main.py        # Точка входа
├── parser.py      # Разбор команд и значений
└── utils.py       # Работа с JSON-файлами
```

Метаданные хранятся в `db_meta.json`, записи — в `data/<таблица>.json`.
Пути считаются от текущей рабочей директории. Запускайте программу из одной
папки, чтобы работать с той же базой. Файлы данных и локальные артефакты
исключены через `.gitignore`.

Это однопоточная учебная база: конкурентная запись и транзакции не реализованы.
Код использует стандартные модули `json`, `shlex`, `time`, `os` и внешние
библиотеки `prompt`, `prettytable`; Ruff используется только при разработке.

## Декораторы и замыкания

- `handle_db_errors` перехватывает `FileNotFoundError`, `KeyError`, `ValueError`,
  ошибки файловой системы и другие исключения. Вложенная ошибка прерывает всю
  операцию; сообщение печатается один раз на внешней границе. Возвращается
  отдельный маркер `DB_ERROR`, который нельзя принять за список записей.
- `confirm_action(action_name)` запрашивает подтверждение для `drop_table`
  и `delete`. Только точный ответ `y` разрешает операцию. Любой другой ответ
  отменяет её без сохранения данных и без сообщения об успешном удалении.
- `log_time` измеряет `insert` и `select` через `time.monotonic()`.
  Вывод: `Функция select выполнилась за 0.000 секунд`. Нулевое значение
  после округления нормально для маленьких таблиц.
- `create_cacher()` возвращает `cache_result(key, value_func)` со словарём
  в замыкании. Повторный ключ не вызывает `value_func`. Ошибки не кэшируются;
  лимит кэша задан в `constants.py`, после его достижения кэш очищается.
- Ключ кэша `select` содержит данные и условие, поэтому изменения таблицы
  учитываются. Записи возвращаются как независимые копии. Файлы всё равно
  читаются, а ключ сериализуется; ускорение небольших запросов не гарантируется.

Обёртки сохраняют имя, документацию и `__wrapped__` исходных функций через
собственную функцию `preserve_metadata`, без дополнительных импортов.

## Проверки и сборка

```bash
make lint
make test
make build
uvx twine check dist/primitive_db-0.5.1*
uv tool install --force dist/primitive_db-0.5.1-py3-none-any.whl
database
```

`make test` запускает функции из `tests/` без тестовых фреймворков.
Каждый тест получает отдельную временную папку, которая удаляется после теста.
Проверяются CRUD, сохранение, типы, кавычки, ID, обработка ошибок, подтверждение,
отмена удаления, таймер и актуальность кэша. Наличие ошибки даёт ненулевой
код завершения. Можно также запустить `uv run python tests/run_tests.py`.

GitHub Actions (`.github/workflows/check.yml`) запускает установку, линтер,
тесты и сборку на push и pull request. Результат смотрите во вкладке Actions.
Эти проверки дополняют тесты преподавателя, но не заменяют их.
Настройка CI основана на [документации uv](https://docs.astral.sh/uv/guides/integration/github/).

Для следующих изменений используйте Github Flow: отдельная ветка,
осмысленные коммиты, push, pull request, проверка Actions и слияние в `main`.
Успешный локальный тест сам по себе не подтверждает принятие работы
автоматической системой преподавателя.
